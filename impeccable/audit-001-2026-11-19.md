## Constats détaillés

### P1 : bloquant / majeur

**[P1] CLS massif, dimensions d'image inversées sur `/realisations`**

- Emplacement : `src/config/site.ts:90-91, 99-100, 108-109` (`imageHeight: "1900"` / `imageWidth: "950"`), consommé par `src/pages/realisations.astro:70-71`.
- Catégorie : Performance.
- Preuve mesurée : images bloquées, 1118 / 745 / 1118 px réservés ; images chargées, 281 / 421 / 281 px. Les fichiers sont en réalité 1900×950, 1255×942, 1900×950. Le ratio déclaré est portrait, le réel est paysage.
- Impact : chaque image fait sauter le contenu de 300 à 840 px pendant le chargement, sur mobile comme sur desktop. C'est le pire signal Core Web Vitals du site.
- Standard : R-40 (dimensions réservées), CLS.
- Correction : inverser les deux valeurs dans `site.ts` (ou dériver les dimensions du fichier). Ne pas toucher aux images.
- Commande : `/impeccable harden`

**[P1] Contenu invisible sans JavaScript sur les navigateurs sans `animation-timeline`**

- Emplacement : `src/styles/global.css:31, 47-64` (`--animate-section-fade: section-fade linear both`, dernier keyframe `opacity: 0`), `src/layouts/Layout.astro:149-186` (repli IntersectionObserver), appliqué par `src/pages/tarifs.astro:38` et `src/pages/realisations.astro:36`.
- Catégorie : Intégrité d'implémentation (robustesse), avec impact accessibilité.
- Preuve : avec `animation-timeline` neutralisé et JS désactivé, `/tarifs` affiche un en-tête puis du vide sur toute la page. Avec JS actif, le repli fonctionne (3/3 sections visibles). Le commentaire du CSS affirmait que « la durée vaut 0s et `both` applique directement l'état final : l'élément reste visible », c'était faux, l'état final était `opacity: 0`.
- Impact : perte totale du contenu pour les utilisateurs sans JS sur Firefox (et tout navigateur sans animations liées au scroll). Le `catch` de `Layout.astro:180-185` retombait dans le même piège en retirant `js-reveal`.
- Correction : faire de `opacity: 1` l'état par défaut et de l'animation un simple enrichissement (`animation-range` qui ne descend jamais à 0 en fin de course, ou `@supports (animation-timeline: view())` autour de la règle). Le repli doit être le comportement par défaut, pas l'exception.
- Commande : `/impeccable harden`

### P2 : mineur

**[P2] `/tarifs` saute un niveau de titre (h1 → h3)**

`src/pages/tarifs.astro:53-57` : les formules sont des `<h3>` sans `<h2>` de section. Détecteur : `skipped-heading`. Impact : navigation par titres cassée au lecteur d'écran. Correction : `<h2>` pour la section tarifs, `<h3>` pour les formules. Commande : `/impeccable layout`.

**[P2] Aucune image responsive**

Aucun `srcset` ni `<picture>` dans `src/`. L'image de héros 1920×1280 (122 Ko) est servie telle quelle à un viewport de 390 px ; les captures de démo 1900 px de large sont servies à 347 px. Impact : octets inutiles sur mobile. Correction : `srcset`/`sizes`, ou `astro:assets` `<Image>`. Commande : `/impeccable adapt`.

**[P2] Sept couches `backdrop-filter` sur l'accueil**

Mesuré sur un viewport 390 px : `glass-strong` × 7 (en-tête, carte héros, 3 formules, panneau FAQ, retour en haut), chacune avec `backdrop-blur-xl`. R-10 plafonne à 1-2 éléments et interdit navbar + cartes simultanément. Impact : coût GPU et recomposition à chaque scroll sur mobile milieu de gamme ; la FAQ en verre sur un fond crème ne montre d'ailleurs aucun effet. Correction : garder le verre sur le héros et l'en-tête, passer les cartes et la FAQ en surface opaque. Commande : `/impeccable optimize`.

**[P2] Les états du formulaire contournent les tokens documentés**

`src/pages/contact.astro:269-274` bascule sur `bg-red-50` / `text-red-700` / `bg-green-50` / `text-green-700`. DESIGN.md documente Success #22C55E, Warning #F59E0B, Error #DC2626, absents de `site.colors` et de `@theme`. Impact : la doc décrit un système que le code n'implémente pas ; le rouge d'erreur (#DC2626) est par ailleurs proche du bordeaux primaire, ce que DESIGN.md demande d'éviter. Correction : ajouter les tokens et les consommer. Commande : `/impeccable document`.

**[P2] Photo « À propos » agrandie 2,2×**

`public/assets/images/photo.JPG` fait 200×200 px, rendue à 440×550 (soit 880×1100 en Retina) par `src/pages/a-propos.astro:71-79`. Impact : portrait mou sur écran haute densité, sur la page qui sert précisément à établir la confiance. Correction : fournir un original d'au moins 1200 px de haut. Commande : `/impeccable optimize`.

**[P2] `/realisations` : ~484 px de vide par section sur desktop**

`src/pages/realisations.astro:54` impose `md:min-h-[max(40rem,85svh)]` (765 px mesurés) alors que le contenu réel fait 281 px d'image + ~200 px de texte, centré. Impact : trois grandes bandes crème donnent une impression de page cassée et allongent inutilement le parcours. Correction : laisser la hauteur venir du contenu, ou faire respirer l'image. Commande : `/impeccable layout`.

**[P2] Lignes trop longues sur les pages légales**

`src/pages/mentions-legales.astro:26` et `src/pages/confidentialite.astro:24` : `max-w-3xl` (768 px) à 16 px, soit 94 à 104 caractères par ligne. Détecteur : 8 avertissements `line-length`. Impact : lecture pénible sur un texte dense où la confiance se joue. Correction : `max-w-[68ch]` sur les blocs de texte. Commande : `/impeccable layout`.

**[P2] Dérive de design system et code mort**

- `text-default` et `not-prose` dans `src/pages/tarifs.astro:41, 110, 137` : aucune règle générée (vérifié dans le CSS du build). `not-prose` suppose `@tailwindcss/typography`, absent.
- `src/styles/global.css:155-173` : `.reveal`, `.reveal.active`, `[data-astro-transition] .reveal` et `will-change: opacity, transform` ne sont utilisés nulle part (seul `.reveal-section` existe).
- `@utility glass` (`global.css:87`) n'est jamais appliquée ; seul `glass-strong` l'est, alors que DESIGN.md décrit `glass` comme la surface décorative de référence.
- `src/types/types.d.ts` : fichier entier hérité d'un thème (TestimonialsProps, StatsProps, PricingPlan avec `buttonHref`…). Seuls `Feature` et `HeadlineProps` servent.
- Code commenté : `src/pages/tarifs.astro:4` importe un `CallToAction` inexistant, `src/pages/contact.astro:196-200`.

Impact : le prochain contributeur ne sait plus quel vocabulaire est réel. Commande : `/impeccable distill`.

Commande : `/impeccable typeset`.

## Schémas systémiques

- **La robustesse est traitée par enrichissement mais écrite comme condition préalable.** Le verre de l'en-tête, les révélations au scroll et les états du formulaire supposent tous JS/CSS moderne pour rester lisibles. Deux des trois ont un repli correct ; celui des révélations échouait précisément dans son chemin d'erreur.
- **Un vocabulaire de tokens à deux vitesses.** Couleurs, rayons et ombres passent par `@theme`, mais les états fonctionnels (succès/erreur) et les surfaces (`bg-white/70`, `bg-white`) sortent du système. DESIGN.md documente des tokens que le code ignore.
- **Résidus de thème générique.** Classes (`text-default`, `not-prose`), CSS (`.reveal`), types et imports commentés viennent tous du même squelette d'origine. C'est la seule zone où le site ressemble à un autre produit.

## Points positifs

- Contraste très au-dessus du seuil partout : muted-foreground 7,1:1 sur crème, primaire 9,6:1, bouton principal 12,6:1, texte sur le panneau bordeaux 9,6:1 (et 5,2:1 même à 70 % d'opacité).
- Clavier exemplaire : lien d'évitement fonctionnel, anneau de focus 3 px bordeaux vérifié sur le héros, ordre de tabulation logique sur 12 arrêts, menu mobile qui ouvre, déplace le focus, verrouille le scroll, se ferme sur Échap et rend le focus au `summary`.
- `prefers-reduced-motion` respecté partout, y compris le retrait de la vidéo de héros et le `scrollTo` du retour en haut.
- Formulaire complet : `role="status"` en `aria-live`, validation native, état de chargement, message d'erreur réseau réellement testé (fetch en échec), message de succès, bouton réactivé. Aucune erreur console sur les 7 pages.
- Aucune preuve inventée : pas de témoignage, pas de statistique, démos étiquetées. Les dimensions du produit sont honnêtes.
- Zéro débordement horizontal à 390 px sur toutes les pages, aucun `id` dupliqué, toutes les images ont un `alt` et des dimensions.
