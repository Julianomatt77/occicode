# Audit antislop 002, 2026-11-04

Périmètre : tout le projet (index.astro, composants Header/Footer, Button, Headline, DemoShowcase, global.css, site.ts, Layout.astro, DESIGN.md).

Source : audit manuel appliquant les règles antislop R-01 à R-40 du
`.opencode/skills/antislop/SKILL.md`. Chaque constat cite la règle violée et la
raison en une ligne. Priorité : Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality
Lock = LOW.

## Constats

| #   | Priorité | Règle | Constat                                                            | Raison                                                                                                                                                                                                                                           |
| --- | -------- | ----- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | HIGH     | R-03  | Cibles tactiles du pied de page insuffisamment grandes             | Les liens du pied de page n'ont pas de `min-height` défini height, ils affichent probablement moins de 44 px de hauteur cliquable, en dessous du minimum requis.                                                                                 |
| 2   | MEDIUM   | R-31  | Aucune raison écrite d'une ligne pour les décisions de design clés | Le DESIGN.md fixe les dials (ENERGY 1 / RHYTHM 2 / MOTION 1) mais les décisions individuelles dans le code (choix de layout, d'espacement, de composition de sections) neDocumentent pas de raison explicite d'une ligne conformément à R-31.    |
| 3   | LOW      | R-19  | Buts d'animation sans but UX écrit documenté                       | Les animations "reveal" par défaut utilisent `transition-opacity transform 0.6s ease-out` ; le but UX (reveal on scroll) n'est pas écrit comme raison explicite dans le code.                                                                    |
| 4   | LOW      | R-03  | Largeur de cible du menu mobile juste suffisante                   | Les liens du menu mobile ont `min-h-11` (44 px) + `px-2` (16 px de padding horizontal) ; la hauteur est exactly 44 px, ce qui est la limite minimale — tout retrait de padding ou changement de taille de police rendrait la cible insuffisante. |

## Vérifications — États conformes (déjà corrigés ou non applicables)

Les éléments suivants étaient des constats dans l'audit précédent mais sont **corrigés** ou **dépassés** :

- ✅ R-17 : Statistique "partout en France" — la ponctuation double point a été corrigée (point simple maintenant).
- ✅ R-03 / R-40 : Image du hero — maintenant en `<img>` avec `fetchpriority="high"` et dimensions width/height.
- ✅ R-36 : Aucune revendication fabriquée — les trust items du hero ("Basé à Péret", "partout en France", "Réponse sous 48h") sont de vraies affirmations sur l'entreprise.
- ✅ R-37 : Direction de design présente dans DESIGN.md avec les trois dials.
- ✅ R-02 : Aucun character `—` (em dash) dans le code.
- ✅ R-25 : Tous les contrastes de texte respectent le WCAG AA (foreground/background 18.46:1, muted-foreground/background 7.21:1, primary/background 6.00:1).
- ✅ R-29 : Palette de couleurs — seulement 2 couleurs non-néutres (foreground #0a0a0a + primary #0254d8), soit 1 core + 1 accent dans la limite de 2-3 core + 1 accent autorisée. Les gris (muted, border, muted-foreground) sont des neutres qui ne comptent pas.
- ✅ R-39 : Structure HTML correcte — `<html lang="fr">`, `<title>`, landmarks (header/nav/main/footer), un h1, pas de `user-scalable=no`.
- ✅ R-04 / R-09 : Icônes MDI utilisées de façon fonctionnelle (check, phone, email, arrow) — pas d'icônes "AI Powered/Beta/New/Secure/Fast" ni de combinaisons capsule+border+glow+dot+uppercase.
- ✅ R-24 : Tous les liens de navigation ont de vraies destinations (pages existantes ou ancres).
- ✅ R-18 : Aucune tentative de témoignages IA ou avatars fictifs.
- ✅ R-14 : Cartes d'arguments — remplacées par des colonnes "Pourquoi OcciCode" à deux colonnes sans icônes identiques.
- ✅ R-32 / R-03 : Anneau de focus 3 px `--primary` dans global.css, visible sur fond clair et sombre.
- ✅ R-40 : Image hero en `<img>` avec `width`/`height`/`fetchpriority="high"`, pas d'image `background-image`.
- ✅ R-26 / R-27 : Tous les éléments interactifs ont un comportement réel ; pas d'éléments "dead". La FAQ utilise `<details>` avec état ouvert/fermé.
- ✅ R-28 : FAQ contient des questions spécifiques au produit, pas de modèles génériques.
- ✅ R-23 : Les actifs existants (logos, images, statistiques) ont été validés ou sont des placeholders honnêtes.
